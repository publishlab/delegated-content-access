Delegated content access

Simulation only: a publisher seals two articles. A client unlocks the first one, the clock crosses a period boundary, and the second article opens out of the cache without reaching the issuer. When selected, the fallback can authorize only while the server's time-bounded demo emergency window is active; primary failure alone grants nothing.

Each control is an argument to run(). Client-bound hands the client key handles rather than bytes, which a store of strings cannot keep, so that run caches in memory, the way a real one would need IndexedDB. The emergency window belongs to this demo rather than to any deployment profile: the simulated emergency authorization is constructed on the issuer, and these controls and request fields cannot enable it.
